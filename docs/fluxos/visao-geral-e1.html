2. Diagrama de Contêineres

Usuários: estudante e responsável pela moradia.

Frontend: telas do estudante e do responsável.

Backend: regras de negócio, busca, compatibilidade e autenticação.

Banco de Dados: PostgreSQL com usuários, vagas, questionários e favoritos.

Serviço externo: envio de e-mails por SMTP.

Fluxo principal: estudante/responsável → Frontend → Backend → Banco de Dados

O Backend também se comunica com o serviço externo de e-mail para envio de notificações.

3. Convenção de Nomes

Idioma: português, sem acentos, em todos os nomes de campos, rotas e operações.

  • Campos entre módulos/API/JSON: camelCase. Ex.: valorAluguel, regrasCasa, criadoEm.
  • Campos no banco: snake_case. Ex.: orcamento_min, distancia_maxima, criado_em.
  • Tabelas: no singular. Ex.: estudante, vaga, favorito.
  • Valores fixos de domínio: snake_case minúsculo. Ex.: em_analise, antes_das_22.
  • Operações: verbo no infinitivo + objeto, em camelCase. Ex.: cadastrarVaga, buscarVagas.
  • Rotas HTTP: prefixo /api/ e substantivos no plural, em minúsculas. Ex.: /api/vagas.
  • Códigos de erro: em maiúsculas com underscore. Ex.: VAGA_NAO_ENCONTRADA.

Fluxo do E1: Cadastro de perfil do estudante

Feito quando: O estudante preenche nome, e-mail, curso, faixa de orçamento e distância máxima do campus, salva, e o perfil aparece na tela “Meu perfil” com os dados que ele digitou.

Passos

  1. O estudante preenche o formulário de perfil e clica em “Salvar”.
  2. O Frontend envia os dados do perfil para o Backend através da operação cadastrarPerfil (CT1).
  3. O Backend valida os dados recebidos (campos obrigatórios e formatos).
  4. O Backend grava as informações no Banco de Dados na tabela estudante (CT2).
  5. O Backend grava o acesso do estudante (e-mail, senha criptografada e perfil) na tabela usuario do Banco de Dados (CT8).
  6. O Banco de Dados confirma a gravação.
  7. O Backend responde ao Frontend confirmando o cadastro do perfil.
  8. O Frontend redireciona o estudante e exibe a tela “Meu perfil” com os dados atualizados.

Diagrama do fluxo

Estudante → Frontend: preenche dados e clica em “Salvar”

Frontend → Backend: CT1 cadastrarPerfil

Backend → Banco: grava em estudante e usuario

Banco → Backend: confirmação de gravação

Backend → Frontend: resposta de perfil criado

Frontend → Estudante: exibe tela “Meu perfil” com os dados salvos

Contratos usados: CT1 cadastrarPerfil, CT2 estudante, CT8 usuario.
